# Token Review — セッションのトークン消費診断

現在のセッションを分析し、トークン浪費の兆候を特定して、優先度付きの改善アクションを提示する。

## 手順

### 1. 情報収集

まず自分で確認できるものを確認する:

- **会話履歴の観察**: 現在のコンテキストに見えている範囲で、(a) 大きなツール出力(テスト結果全文、長大なログ、大きなファイルの全文Read)、(b) 既に完了して現在のタスクと無関係になった話題、(c) 同じファイルの繰り返しRead、を洗い出す。
- **CLAUDE.md のサイズ**: プロジェクトルートと `~/.claude/CLAUDE.md` を `wc -l` で確認。200行超なら肥大。
- **セッションのタスク数**: この会話で扱ったタスクが2つ以上あるか(タスク混在はコンテキスト浪費の最大要因)。

次に、自分では取得できない情報をユーザに依頼する(必要な場合のみ):

- `/context` の出力貼り付け → MCPサーバ・スキル・システムプロンプトの内訳が必要なとき
- `/usage` の出力貼り付け → モデル別消費や long context / cache miss のフラグが必要なとき

すべてを毎回依頼しないこと。会話履歴だけで診断が明確なら依頼を省く。

### 2. 診断

`references/cost-best-practices.md` を読み、各チェック項目に照らして評価する。主なカテゴリ:

1. コンテキスト管理(/clear のタイミング、タスク混在)
2. モデル選択(タスクに対して過剰なモデルか)
3. MCPサーバのオーバーヘッド(未使用サーバ、CLIで代替可能なもの)
4. CLAUDE.md の肥大(スキルへの移動候補)
5. extended thinking の effort 設定
6. 冗長な処理のsubagent委譲・hookによる前処理
7. プロンプトの具体性
8. long context / cache miss / スケジュールタスクなどセッション運用要因

### 3. レポート出力

以下の形式で簡潔に(見つかった項目のみ。該当なしのカテゴリは書かない):

```
## 検出した無駄遣い

1. [兆候] — [推定影響: 高/中/低]
   → 改善: [具体的アクション。実行するコマンドがあれば明記]
```

最後に「今すぐやるべき1つ」を1行で示す。ユーザが実行するコマンド(`/clear`, `/rename`, `/compact <指示>`, `/model`, `/mcp`, `/effort` など)は必ず具体的に書く。

## 注意

- このスキル自体の分析でツールを乱発しない。`wc -l` 程度の軽量な確認に留め、コードベースの探索はしない。
- 断定できないものは「可能性」として提示し、確認方法(/context, /usage)を添える。
- 説教調にならない。改善は最大5項目、優先度順。
