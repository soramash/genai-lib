# Claude Code トークン削減ベストプラクティス(診断チェックリスト)

出典: https://code.claude.com/docs/en/costs.md の要点を診断用に再構成したもの。

## 1. コンテキスト管理

- Claude Codeは毎メッセージで会話全体を送信する。長時間開いたセッションでの一言の質問も、全履歴分のトークンを消費する。
- **チェック**: セッション内に無関係なタスクが混在していないか。完了済みタスクの残骸が残っていないか。
- **改善**: 無関係な作業に移る前に `/rename` → `/clear`。後で `/resume` で戻れる。
- `/compact <保持したい内容の指示>` で要約時の焦点を制御できる。ただしcompact自体が大きなリクエストになるため、継続不要なら `/clear` の方が安い(コストゼロ)。
- CLAUDE.md に `# Compact instructions` セクションを書いて要約方針を恒久化できる。

## 2. モデル選択

- 多くのコーディングタスクはSonnetで十分。Opusはアーキテクチャ判断や複雑な多段推論に限定する。
- **チェック**: 単純作業(定型修正、ドキュメント、小さなバグ修正)にOpusを使っていないか。
- **改善**: `/model` でセッション途中に切替、`/config` でデフォルト設定。subagentには `model: haiku` 指定も可。

## 3. MCPサーバのオーバーヘッド

- MCPツール定義はデフォルトで遅延ロードされるが、ツール名は常にコンテキストに入る。
- **チェック**: `/context` でMCP・スキルの消費割合を確認。使っていないサーバがないか。
- **改善**: `/mcp` で未使用サーバを無効化。`gh` `aws` `gcloud` などCLIがある場合はMCPよりCLIの方がコンテキスト効率が良い。

## 4. CLAUDE.md の肥大

- CLAUDE.md はセッション開始時に常時ロードされる。特定ワークフロー向けの詳細手順(PRレビュー、DBマイグレーション等)が入っていると、無関係な作業中もトークンを占有する。
- **チェック**: 200行を超えていないか。特定作業専用のセクションがないか。
- **改善**: ワークフロー固有の指示はスキルに切り出す(スキルは呼び出し時のみロード)。

## 5. Extended thinking

- thinkingトークンは出力トークンとして課金され、デフォルト予算はモデルによってリクエストあたり数万トークンになりうる。
- **改善**: 単純タスクでは `/effort` でeffortを下げる、`/config` でthinkingを無効化、固定予算モデルでは `MAX_THINKING_TOKENS` 環境変数で予算を下げる。(注: Fable 5 はthinking無効化不可)

## 6. 冗長処理の委譲・前処理

- テスト実行、ドキュメント取得、ログ処理などの冗長な出力はメインコンテキストを圧迫する。
- **改善(subagent)**: 冗長な操作をsubagentに委譲すれば、詳細出力はsubagent側に留まり、要約だけがメインに戻る。
- **改善(hook)**: PreToolUse hookでツール出力を前処理できる。例: テストコマンドを失敗行のみ表示するよう書き換えれば、数万トークンのログが数百トークンになる。
- 型付き言語ではcode intelligenceプラグイン(LSP)導入で、grep+複数ファイルReadを「定義へ移動」1回に置き換えられる。

## 7. プロンプトの具体性

- 「このコードベースを改善して」のような曖昧な依頼は広範なスキャンを誘発する。
- **改善**: 「auth.ts の login関数に入力バリデーションを追加」のように対象を特定する。検証ターゲット(テストケース、期待出力、スクリーンショット)を与えると手戻りが減る。
- 複雑なタスクは plan mode(Shift+Tab)で方針承認してから実装、脱線したら早期にEscで停止し `/rewind` する。

## 8. セッション運用要因(長時間セッションで消費が跳ねる理由)

- **long context**: 上記1と同じ。全履歴が毎回送られる。
- **cache miss**: キャッシュ寿命(サブスクリプションで1時間、usage credit消費中/APIキーで5分)を超える休憩の後の最初のメッセージは全コンテキストを再処理する。
- **scheduled tasks**: スケジュールタスクはアイドル中も全コンテキスト付きで発火する。
- **agent teams**: teammateは終了するまで消費し続ける。plan modeのteammateは通常の約7倍のトークンを使う。小さなチーム・focused spawn prompt・完了後の即shutdownが原則。
- `/usage` は直近使用量の10%以上を占める要因(long context, cache miss等)をフラグしてくれる。

## 診断時の優先順位の目安

影響が大きい順: (1) タスク混在・長期セッションの放置 → /clear、(2) モデル過剰 → /model、(3) extended thinking effort、(4) MCP/CLAUDE.md肥大、(5) 冗長出力の委譲・前処理。
